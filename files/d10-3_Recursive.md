# ใบความรู้ เรื่อง ฟังก์ชันเวียนบังเกิด (Recursive) ด้วย C++

## 1. แนวคิดและกฎสองข้อของ Recursive

ฟังก์ชันเวียนบังเกิด (recursive function) คือฟังก์ชันที่เรียกตัวเอง เพื่อแก้ปัญหาใหญ่ด้วยการแก้ปัญหาเดิมที่เล็กลง แล้วนำคำตอบมาประกอบกัน

**ตัวอย่างนับจำนวนคนในแถว** คนหน้าสุดไม่รู้ว่าข้างหลังมีกี่คน จึงถามคนข้างหลังต่อ ๆ กันไป

- กรณีฐาน : ถ้าไม่มีใครอยู่ข้างหลัง ตอบ 0 ทันที
- กรณีเวียนเกิด : ถามคนข้างหลังว่าเหลือกี่คน แล้วตอบ 1 + คำตอบนั้น

**กฎสองข้อที่ต้องมีเสมอ**

1. กรณีฐาน (base case) คือกรณีที่เล็กจนตอบได้ทันที และไม่เรียกตัวเองอีก
2. กรณีเวียนเกิด (recursive case) คือการเรียกตัวเองด้วยปัญหาที่เล็กลง และทุกครั้งต้องเข้าใกล้กรณีฐาน

โครงมาตรฐานของฟังก์ชันเวียนบังเกิดใน C++

```cpp
type f(problem) {
    if (problem is small enough)   // กรณีฐาน
        return answer;
    return combine(f(smaller));    // กรณีเวียนเกิด
}
```

**หัวใจของ recursion** คือเชื่อว่าฟังก์ชันของเราแก้ปัญหาที่เล็กกว่าได้ถูกต้องแล้ว ไม่ต้องจำลองทุกชั้นในหัว เหลือเพียงทำส่วนของเราให้ครบ คือตั้งกรณีฐานและประกอบคำตอบ

**ข้อผิดพลาดที่พบบ่อย** คือลืมกรณีฐาน หรือเรียกด้วยปัญหาที่ไม่เล็กลง ทำให้เรียกไม่รู้จบจน stack เต็ม ใน C++ โปรแกรมจะล้มด้วย Runtime Error (segmentation fault) ไม่มีข้อความ RecursionError แบบ Python

```cpp
int bad(int n) {
    return n + bad(n - 1);   // ไม่มีกรณีฐาน เรียกไม่รู้จบ
}
```



## 2. call stack และการ trace

ทุกครั้งที่เรียกฟังก์ชัน โปรแกรมจะจองพื้นที่หนึ่งช่องใน call stack เก็บค่าพารามิเตอร์ของการเรียกนั้น การทำงานแบ่งเป็นสองช่วง คือ **ขาลง** (เรียกซ้อนลงไปจนถึงกรณีฐาน) และ **ขาขึ้น** (คืนค่ากลับมาประกอบคำตอบทีละชั้น)

```cpp
long long factorial(int n) {
    if (n <= 1) return 1;              // กรณีฐาน
    return n * factorial(n - 1);       // กรณีเวียนเกิด
}
```

**trace factorial(4)**


| เรียก        | ต้องรอผลของ      | คืนค่า |
| ------------ | ---------------- | ------ |
| factorial(4) | 4 × factorial(3) | 24     |
| factorial(3) | 3 × factorial(2) | 6      |
| factorial(2) | 2 × factorial(1) | 2      |
| factorial(1) | กรณีฐาน          | 1      |


ขาลงเรียกจาก factorial(4) ลงไปถึง factorial(1) ทั้งสี่ชั้นค้างอยู่ใน stack พร้อมกัน ขาขึ้นคืนค่า 1 → 2 → 6 → 24 ตามลำดับ

**พิมพ์ก่อนเรียก กับ พิมพ์หลังเรียก** คำสั่งที่อยู่ก่อนการเรียกตัวเองทำตอนขาลง ส่วนคำสั่งที่อยู่หลังทำตอนขาขึ้น ลำดับจึงย้อนกลับ

```cpp
void down(int n) {            // down(3) พิมพ์ 3 2 1
    if (n == 0) return;
    cout << n << " ";
    down(n - 1);
}
void up(int n) {              // up(3) พิมพ์ 1 2 3
    if (n == 0) return;
    up(n - 1);
    cout << n << " ";
}
```

เทคนิคนี้ใช้ตอนแปลงเลขฐาน (หัวข้อ 7)

## 3. ตัวอย่างพื้นฐาน: factorial ผลรวม และ ห.ร.ม.

สามเรื่องนี้มีรูปร่างเดียวกัน คือ "ทำงานเล็กน้อยหนึ่งอย่าง แล้วฝากส่วนที่เหลือให้การเรียกตัวเอง"

**3.1 ผลรวม 1 ถึง n**

คิดว่า sumto(n) = n + sumto(n−1) และ sumto(0) = 0

```cpp
int sum_to(int n) {
    if (n == 0) return 0;        // กรณีฐาน
    return n + sum_to(n - 1);    // กรณีเวียนเกิด
}
```

ตัวอย่าง sumto(4) = 4 + 3 + 2 + 1 + 0 = 10

**3.2 ห.ร.ม. ด้วยวิธีของยุคลิด**

หลักการ gcd(a, b) = gcd(b, a mod b) และ gcd(a, 0) = a

```cpp
int gcd_rec(int a, int b) {
    if (b == 0) return a;        // กรณีฐาน
    return gcd_rec(b, a % b);    // เรียกตัวเองเป็นคำสั่งสุดท้าย
}
```

ตัวอย่างการ trace gcdrec(84, 36)


| ลำดับ | การเรียก       | a mod b            |
| ----- | -------------- | ------------------ |
| 1     | gcdrec(84, 36) | 84 mod 36 = 12     |
| 2     | gcdrec(36, 12) | 36 mod 12 = 0      |
| 3     | gcdrec(12, 0)  | b = 0 จึงคืนค่า 12 |


คำตอบคือ 12 ฟังก์ชันนี้ไม่มีงานเหลือหลังการเรียก จึงเรียกว่า tail recursion

**จุดที่เหมือนกัน** ของ factorial, sumto และ gcdrec

- มี if ที่คืนค่าได้ทันทีอยู่บรรทัดแรก
- ปัญหาที่ส่งไปให้การเรียกถัดไป เล็กลงทุกครั้ง (n ลดลง หรือ b เล็กลง)



## 4. ฟีโบนัชชี: ทำไมช้า และแก้อย่างไร

นิยาม fib(0) = 0, fib(1) = 1 และ fib(n) = fib(n−1) + fib(n−2)

```cpp
long long fib(int n) {
    if (n <= 1) return n;               // กรณีฐาน มี 2 กรณี
    return fib(n - 1) + fib(n - 2);     // เรียกตัวเอง 2 ทาง
}
```

**ทำไมช้า** เพราะเรียกปัญหาย่อยเดิมซ้ำหลายรอบ เช่น fib(5) ต้องคำนวณ fib(3) สองครั้ง และ fib(2) สามครั้ง


| ค่า n | จำนวนครั้งที่เรียก fib |
| ----- | ---------------------- |
| 5     | 15                     |
| 10    | 177                    |
| 30    | 2,692,537              |


เมื่อ n เพิ่มขึ้น 1 งานเพิ่มประมาณ 1.6 เท่า จึงโตแบบเอกซ์โพเนนเชียล (ขอบบนหลวม ๆ คือ O(2^n)) ถ้าโจทย์จำกัดเวลา 1 วินาที n ระดับ 40 ขึ้นไปจะไม่ผ่านถ้าไม่จำคำตอบ

**วิธีแก้: จำคำตอบไว้ (Memoization)**

```cpp
long long memo[100];   // ก่อนเรียก: memset(memo, -1, sizeof memo);

long long fibm(int n) {
    if (n <= 1) return n;
    if (memo[n] != -1) return memo[n];            // เคยคำนวณแล้ว คืนเลย
    return memo[n] = fibm(n - 1) + fibm(n - 2);   // คำนวณแล้วจดไว้
}
```

- เวลาเหลือ O(n) เพราะแต่ละ n คำนวณครั้งเดียว
- fib(50) = 12,586,269,025 ได้ทันที
- fib(92) เป็นค่ามากสุดที่ long long เก็บได้
- ต้อง memset memo เป็น −1 ก่อนเรียกทุกครั้ง ถ้าลืมจะได้ค่าผิด

นี่คือก้าวแรกของ Dynamic Programming แบบ top-down

## 5. สูตรคิด 4 ขั้นแบบแบ่งเป็นปัญหาย่อย

ทุกโจทย์ recursive คิดตามขั้นตอนนี้ได้

1. **หากรณีฐาน** ปัญหาเล็กสุดที่ตอบได้ทันทีคืออะไร
2. **สมมติ** ว่าปัญหาที่เล็กกว่า แก้ได้แล้ว
3. **ประกอบ** คำตอบย่อยเป็นคำตอบของปัญหาใหญ่
4. **ตรวจ** ว่าทุกการเรียกเข้าใกล้กรณีฐาน

ตัวอย่างกับ factorial: ① n ≤ 1 → 1 · ② สมมติ (n−1)! ได้แล้ว · ③ n × (n−1)! · ④ n ลดลงทีละ 1 จึงถึงกรณีฐานแน่

ขั้นที่ 4 สำคัญที่สุดเวลาเขียนโจทย์แข่ง เพราะป้องกันการเรียกไม่รู้จบ ลองใช้ 4 ขั้นนี้กับ sumto, gcdrec และ fib ด้วยตัวเอง

## 6. ยกกำลังแบบเร็ว (Fast Power) และ mod

**แนวคิด** แทนที่จะคูณ a ซ้ำ b ครั้ง ให้แบ่งเลขชี้กำลังครึ่งหนึ่ง

- b เป็นคู่: a^b = (a^(b/2))²
- b เป็นคี่: a^b = (a^(b/2))² × a (ใช้ b/2 แบบปัดลง)
- b = 0: a^0 = 1 (กรณีฐาน)

```cpp
long long power_fast(long long a, int b) {
    if (b == 0) return 1;
    long long h = power_fast(a, b / 2);   // เรียกแค่ครั้งเดียว เก็บไว้ในตัวแปร h
    if (b % 2 == 0) return h * h;
    return h * h * a;
}
```

ข้อสำคัญ: ต้องเก็บผลใน h แล้วค่อยคูณ หากเขียน powerfast(a, b/2)  powerfast(a, b/2) จะเรียกสองทาง ได้คำตอบถูกแต่กลับช้าเท่าวิธีปกติ เช่น b = 16 เรียกถึง 63 ครั้ง

แบ่งครึ่งทุกครั้ง จึงใช้เวลา O(log b) และ stack ลึกประมาณ log₂ b

ตัวอย่าง powerfast(3, 5): b = 5, 2, 1, 0 ขาลง แล้วขาขึ้น 1 → 3 → 9 → 81 × 3 = 243 คำตอบคือ 243

**ทำไมต้อง mod ทุกขั้น**

ยกกำลังแล้วค่าใหญ่เกิน long long ในไม่กี่ขั้น โจทย์จึงมักถามเศษเมื่อหารด้วย m ใช้คุณสมบัตินี้เพื่อ mod แทรกทุกขั้นได้

```latex
(x \cdot y) \bmod m = \big((x \bmod m)\cdot(y \bmod m)\big) \bmod m
```

```cpp
long long power_mod(long long a, long long b, long long m) {
    if (b == 0) return 1 % m;
    long long h = power_mod(a, b / 2, m);
    h = h * h % m;
    if (b % 2 == 1) h = h * (a % m) % m;
    return h;
}
```

- h  h ต้องไม่เกิน long long จึงใช้ได้เมื่อ m ไม่เกินประมาณ 10^9 + 7 (ผลคูณไม่เกินราว 10^18)
- คืน 1 % m ไม่ใช่ 1 เพราะกรณี m = 1 คำตอบคือ 0
- ตัวอย่างที่ตรวจแล้ว: powermod(2, 10, 1000) = 24 · powermod(3, 200, 1000000007) = 136318165



## 7. แปลงเลขฐานแบบเวียนเกิด

แปลงเลขฐานสิบ n เป็นฐาน b หาร b ซ้ำ แล้วอ่านเศษ **จากล่างขึ้นบน** ซึ่งพอดีกับขาขึ้นของ recursion

- ปัญหาย่อย: แปลง n / b ก่อน (ส่วนหน้าของคำตอบ)
- แล้วค่อยพิมพ์หลักสุดท้าย n % b
- กรณีฐาน: n < b พิมพ์ n ได้เลย

```cpp
void to_base(int n, int b) {
    if (n >= b) to_base(n / b, b);          // แปลงส่วนหน้าก่อน
    cout << "0123456789ABCDEF"[n % b];      // พิมพ์หลังเรียก (ขาขึ้น)
}
```

ตัวอย่าง tobase(13, 2)


| ชั้น | n   | n / 2 | n % 2 (พิมพ์ตอนขาขึ้น) |
| ---- | --- | ----- | ---------------------- |
| 1    | 13  | 6     | 1                      |
| 2    | 6   | 3     | 0                      |
| 3    | 3   | 1     | 1                      |
| 4    | 1   | –     | 1                      |


ขาขึ้นพิมพ์จากชั้นที่ 4 กลับไปชั้นที่ 1 ได้ 1101 ซึ่งตรงกับ 13 ฐานสอง

**ระวัง:** ถ้าสลับให้ cout อยู่ก่อนการเรียก (ขาลง) จะพิมพ์จากหลักที่น้อยไปมาก ได้ผลกลับด้าน (13 ฐาน 2 กลายเป็น 1011)

ตัวอย่างอื่น ที่ตรวจแล้ว: tobase(255, 16) = FF · tobase(100, 8) = 144 · tobase(10, 2) = 1010

ถ้าต้องการคืนค่าเป็นสตริง ใช้แบบนี้: return tobasestr(n / b, b) + Dn % b; (ในแบบฝึกหัด)

## 8. Recursive บนอาร์เรย์ สตริง และ binary search

บนอาร์เรย์มีสองแบบหลัก คือเดินทีละช่องด้วย index i และแบ่งช่วง l, r เป็นสองครึ่ง

**8.1 เดินทีละช่อง (ผลรวมอาร์เรย์)**

```cpp
int sum_arr(int a[], int i, int n) {
    if (i == n) return 0;                  // เกินท้ายอาร์เรย์
    return a[i] + sum_arr(a, i + 1, n);
}
```

**8.2 แบ่งช่วงครึ่งหนึ่ง (หาค่าสูงสุด)**

```cpp
int max_range(int a[], int l, int r) {
    if (l == r) return a[l];               // เหลือช่องเดียว
    int m = (l + r) / 2;
    return max(max_range(a, l, m), max_range(a, m + 1, r));
}
```

ช่วงแบ่งครึ่งทุกครั้ง ความลึกของ stack จึงประมาณ log₂ n แต่ทั้งหมดยังเยี่ยมทุกช่อง เวลา O(n) ตัวอย่าง {3, 8, 1, 9, 4} ได้ 9

**8.3 binary search แบบเวียนเกิด** (อาร์เรย์เรียงจากน้อยไปมาก)

```cpp
int bsearch_rec(int a[], int l, int r, int x) {
    if (l > r) return -1;                  // ไม่พบ
    int m = (l + r) / 2;
    if (a[m] == x) return m;
    if (a[m] < x) return bsearch_rec(a, m + 1, r, x);
    return bsearch_rec(a, l, m - 1, x);
}
```

ทั้ง 3 ทางตัดช่วงทิ้งครึ่งหนึ่ง เวลา O(log n)

**8.4 สตริง: ตรวจประโยคสมมาตร (palindrome)**

```cpp
bool is_pal(const string &s, int l, int r) {
    if (l >= r) return true;               // เหลือ 0 หรือ 1 ตัว
    if (s[l] != s[r]) return false;
    return is_pal(s, l + 1, r - 1);        // ตัดหัวท้ายออก
}
```

ส่งสตริงผ่าน reference (&) เสมอ ถ้าส่งแบบคัดลอก แต่ละชั้นจะคัดลอกสตริงทั้งหมด ช้าและกินหน่วยความจำ

## 9. หอยสามเหลี่ยม (Tower of Hanoi) และความซับซ้อน

ย้ายแผ่นดิสก์ n แผ่นจากเสา A ไป C โดยใช้เสา B ช่วย ย้ายทีละแผ่น และห้ามวางแผ่นใหญ่ทับแผ่นเล็ก

คิดแบบแบ่งปัญหาย่อย 3 จังหวะ: (1) ย้าย n−1 แผ่นบนไป B (2) ย้ายแผ่นใหญ่สุดไป C (3) ย้าย n−1 แผ่นจาก B ไป C

```cpp
void hanoi(int n, char from, char to, char via) {
    if (n == 0) return;
    hanoi(n - 1, from, via, to);
    cout << from << "->" << to << " ";
    hanoi(n - 1, via, to, from);
}
```

hanoi(3, 'A', 'C', 'B') พิมพ์: A->C A->B C->B A->C B->A B->C A->C (7 ครั้ง)

จำนวนครั้งย้าย H(n) = 2H(n−1) + 1 ให้ H(n) = 2^n − 1 (n = 3 → 7, n = 10 → 1,023, n = 20 → 1,048,575)

**ตารางสรุปความซับซ้อนของ recursive**


| สมการ                      | ความซับซ้อน     | ตัวอย่าง                 |
| -------------------------- | --------------- | ------------------------ |
| T(n) = T(n−1) + 1          | O(n)            | factorial, sumto         |
| T(n) = T(n/2) + 1          | O(log n)        | powerfast, binary search |
| T(n) = 2T(n/2) + 1         | O(n)            | maxrange                 |
| T(n) = T(n−1) + T(n−2) + 1 | เอกซ์โพเนนเชียล | fib ไม่จำคำตอบ           |
| T(n) = 2T(n−1) + 1         | O(2^n)          | hanoi                    |

- **ชนิดข้อมูล** factorial และ fib ใช้ long long แต่ 21! ก็ยังล้น ถ้าโจทย์ให้ mod ต้อง mod ทุกชั้น
- **กรณีฐานมาก่อน** เขียน if ที่ return ไว้บรรทัดแรกของฟังก์ชันเสมอ แล้วค่อยเขียนกรณีเวียนเกิด
- **ความลึกของ stack** ซ้อนได้จำกัด (ราวหลักแสนถึงล้านชั้น ขึ้นกับระบบตรวจ) เกินแล้วโปรแกรมจะจบด้วย Runtime Error (segfault) ไม่มีข้อความบอกว่า recursion ถ้า n ใหญ่มากให้ใช้ loop แทน
- **เรียกซ้ำซ้อน** ถ้าเรียกตัวเองหลายทางและปัญหาย่อยซ้ำกัน ให้เพิ่ม memo (DP)
- **เรียกตัวเองสองครั้งโดยไม่จำเป็น** เช่น powerfast ที่ลืมเก็บในตัวแปร h ทำให้ช้าลงมาก
- **ลำดับขาลงและขาขึ้น** พิมพ์ก่อนเรียกได้ลำดับปกติ พิมพ์หลังเรียกได้ลำดับย้อนกลับ

**สรุปสั้น ๆ**

1. Recursive = แก้ปัญหาใหญ่ด้วยปัญหาย่อยรูปแบบเดียวกัน มีกรณีฐานและกรณีเวียนเกิดเสมอ
2. ทุกการเรียกต้องเข้าใกล้กรณีฐาน มิฉะนั้น stack ล้น
3. อ่านการทำงานด้วย call stack: ขาลงทำงานก่อนเรียก ขาขึ้นทำงานหลังเรียก
4. ปัญหาย่อยซ้ำ → memo · แบ่งครึ่ง → log n
5. ทำแบบฝึกหัดในใบงานและรันโค้ดทดลองเอง
